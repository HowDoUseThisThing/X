# 玩法扩展设计：夜潮构筑

> 状态：先形成设计文档，再一次性实现完整扩展；本文现按 2026-11-12 本地工作区同步实现契约。第 10 节保留验收门槛；本地实现与自动化结果见文末和验收报告。
> 目标玩家：桌面与手机各一半；偏策略构筑；接受本地存档；一次性交付完整版本。
> 本文对应策略构筑扩展的当前实现。浏览器、性能与静态包验证结果见 [`acceptance.md`](acceptance.md)；手机硬件体验需真机实测。

## 1. 体验目标

每一局要回答三个问题：**这局想组什么、为什么现在拿它、失败了下次还想试什么。**

- 单局核心：移动躲避 + 自动攻击 + 升级时做构筑选择 + 不同敌人逼迫改变走位 + 首领/事件检验构筑。
- 局外核心：用每局获得的“回响”永久强化，用成就给出明确挑战目标。
- 目标节奏：首个构筑差异 ≤ 60 秒；首个精英 ≤ 2 分钟；首个首领 = 3 分钟；10 分钟后进入高压循环。
- 不做：手动瞄准、复杂的主动技能轮盘、服务器、账号、排行榜。手机操作仍以单摇杆 + 闪避为限。

## 2. 核心循环

```text
进入夜潮 → 击杀/拾取经验 → 升级暂停 → 三选一（武器/升级/被动/进化）
      ↑                                      │
      └── 拾取/宝箱/祭坛 ← 精英/首领/事件 ←──┘
      │
      └── 死亡或主动撤离 → 结算回响 → 永久强化/解锁 → 再开一局
```

- 默认无尽模式；10 分钟后难度持续增长，不硬性结束。
- 玩家可在暂停界面选择“带着回响撤离”，按当前进度结算；死亡同样结算，但少 20% 回响（策略风险表达，不惩罚首次体验）。
- 所有局内随机使用可注入种子的确定性随机；相同种子、开局角色/永久强化、视口、输入/时间步和选择序列应得到相同结果。
- 核心 `start(characterId = null, seed = this.seed)` 接受可选第二参数种子，默认沿用当前种子以便复现；正常 UI 每局生成新种子并避开上一局种子，避免连续重开初始内容相同。种子和局内状态不存档。

## 3. 构筑系统

### 3.1 槽位与规则

- 最多 **4 件武器**、**4 件被动**，共 8 个构筑槽。
- 每件武器 5 级；被动最多 5 级。
- 升级候选池由“已有武器升级 / 已有被动升级 / 新武器 / 新被动 / 可进化项”组成。符合条件的进化保底先入；其余新项权重 1、已有强化权重 2，与已有武器匹配的被动再乘 1.4，按权重无放回抽取。
- 每次升级最多展示 3 项，同一次抽选不重复；合法候选不足 3 项时显示全部合法项，全部满级且没有可进化等合法构筑项时回血兜底，不制造不存在项或重复选项。
- 每局基础 1 次重抽；月蚀游侠额外 +1，初始共 2 次；命运刻印 `fate` 每级再 +1、最多 2 级。因此游侠最多 4 次，另两名角色初始 1 次、最多 3 次。重抽不消耗升级机会。
- 跳过：放弃本次强化，立即获得 `当前等级 × 8` 经验作为追赶补偿；每局最多 2 次。
- 构筑槽满后，不再提供新武器/新被动，但已有项升级仍可出现。
- 进化：武器 5 级 + 对应被动 ≥3 级时，升级池必出一次金色进化项。进化占原武器槽，等级显示为 EVO，不再继续普通升级。
- 宝箱：首领必掉；打开后提供 1 次“宝箱三选一”（只出已有武器/被动升级或进化，不出全新项），可触发进化。
- 宝箱沿用合法候选数量规则：开局只有 1 件初始武器且没有被动时，展示该武器唯一的合法升级即可；无可用构筑项时回血处理。不能为填满三张卡而加入未持有项或重复项。

## 5. 敌人与压迫方式

### 5.1 普通敌人

| 类型 | 行为 | 策略作用 |
| --- | --- | --- |
| `shade` | 直线追踪 | 基础压力 |
| `runner` | 快速追踪，血量低 | 逼玩家保持移动 |
| `brute` | 慢、厚、伤害高 | 逼玩家绕开而非硬吃 |
| `wraith` | 追踪且移动轨迹轻微摆动 | 增加命中判读难度 |
| `gunner`（新） | 保持 220~300px，向玩家发射慢弹 | 逼玩家接近或利用掩体节奏 |
| `charger`（新） | 接近后锁定方向，蓄力 0.7s 后冲锋 | 逼玩家横向闪避 |
| `splitter`（新） | 死亡分裂 2 个小型个体 | 抑制无脑清屏 |
| `bomber`（新） | 接近后延迟爆炸，留下短暂危险区 | 逼玩家主动拉开距离 |

### 5.2 精英与首领

- 首波精英在 2:00 出现，每波随机 2~4 只；高血量、带光晕、掉落宝箱概率 35%。随后间隔按 `max(60, 110 - floor(已存活秒数 / 180) × 15)` 秒缩短，最低 60 秒；波次、精英、首领均提前 3 秒预警。
- 首领在 3:00、6:00、9:00…出现；每阶段拥有 2 种攻击：
  - **潮汐巨像**：环形弹幕 + 召唤 4 只 runner。
  - **雾中执刑者**：冲锋轨迹预警 + 十字弹幕。
- 首领血条常驻顶部，死亡必掉宝箱并回复 20 点生命；已有首领未被击败时不叠加生成第二只。
- 普通怪占满 800 个敌人预算时，定时精英替换普通怪腾位，首领也腾位生成，避免事件因普通怪满额而静默错过；被替换对象不计击杀、不给掉落。
- 10 分钟后普通敌人 HP/速度继续增长：新刷怪 HP 的压力系数含 `max(0, elapsed - 600) / 300`，速度系数含 `max(0, elapsed - 600) / 6000`，均在前期封顶项之外继续累加；精英间隔缩短至下限 60 秒。

### 5.3 时间轴

| 时间 | 变化 |
| --- | --- |
| 0:00 | shade/runner 基础混合 |
| 1:00 | 加入 gunner；第一波圈形包围 |
| 2:00 | 首次精英；加入 charger/splitter |
| 3:00 | 首个首领；加入 bomber |
| 每 3 分钟 | 首领/波次升级；预告条和音效 |
| 10:00+ | 高压循环：精英更频繁、普通怪继续增厚 |

刷怪导演按“基础填充 + 周期波次 + 精英/首领事件”三层工作；所有事件有 HUD 预告（3 秒）和音效，不隐藏信息。

## 6. 掉落、地图互动与节奏

- 经验宝石：普通掉落为主；精英额外掉大宝石。
- 拾取物：心（回血 20%）、磁石（全图吸取 6s）、圣水（8s 范围灼烧）、炸弹（清屏伤害 + 震屏）。掉落概率 4%，精英 35%。
- 宝箱：首领必掉，精英 35%；拾取后进入宝箱三选一。
- 祭坛：固定 3 个遗迹祭坛。站上 2 秒激活：本局诅咒 +1（后续新生成敌人按层数增加 HP，普通敌人同时增加速度），获得 1 次额外宝箱和基础结算回响 +10%。回响加成最多 +60%，诅咒与宝箱次数不受此加成上限限制；激活后祭坛进入 3 分钟冷却。
- 危险区：bomber 爆炸留下的持续区域；对玩家和敌人均造成伤害，创造走位空间。
- 敌方弹体统一只伤玩家，不与敌人做伤害判定，包括 gunner 与首领弹幕；bomber 危险区属于区域伤害，是明确允许伤敌人的独立机制。
- 每 60 秒的潮汐钟声保留，但现在同时触发一次可见的“潮汐脉冲”：屏幕边缘颜色和刷怪速度短暂变化。

## 7. 局外成长与存档

### 7.1 存档

- 使用 `localStorage`，键 `moonlit-survivor-save-v1`；JSON、版本号、校验失败时回退默认值，不阻塞启动。
- 保存：回响余额、永久强化、角色解锁、成就、累计统计、已读引导、声音开关、上次角色。
- 不保存：种子和进行中的局内状态（避免刷新利用和复杂迁移）；刷新回到标题。
- 存档节流：结算、购买、切换角色、设置变化时写入；不在每帧写入。
- 字段按白名单规范化，数值必须有限且非负，永久强化有等级上限；存储缺失/访问异常、损坏 JSON、写盘失败均不能中断游戏。写盘失败时仅能保证当前页面继续使用内存进度，不能宣称刷新后仍已持久保存。
- 实际入口直接复用 `SaveStore` 的内存缓存与失败写入标记，不另设存储子类；结算幂等集合属于 UI 内存，不随存档跨刷新保存，详见架构文档第 11.5～11.6 节。

### 7.2 回响与永久强化

令 `基础值 = 击杀 × 0.6 + 存活秒数 × 0.35 + 首领 × 40 + 等级 × 3 + 宝箱 × 8`，则基础结算回响 = `floor(基础值 × (1 + min(0.6, 祭坛激活次数 × 0.1)) × 死亡系数)`；死亡系数为 0.8，撤离为 1。成就奖励另外相加，不受死亡折扣与祭坛加成影响。取整在乘数之后执行。

除命运刻印最多 2 级外，其余永久强化最多 5 级：

| 强化 | 每级 | 费用曲线 |
| --- | --- | ---: |
| 生命刻印 | 最大生命 +3% | 120 × (级数+1) |
| 余烬刻印 | 伤害 +3% | 150 × (级数+1) |
| 拾光刻印 | 经验 +3% | 130 × (级数+1) |
| 命运刻印 | 每局重抽 +1，共 2 级 | 第 1 级 500，第 2 级 800 |
| 财富刻印 | 拾取物概率 +2% | 160 × (级数+1) |

### 7.3 成就

- 初见黎明：存活 3 分钟。
- 星火成河：单局击杀 500。
- 进化之火：首次完成任意武器进化。
- 夜潮驯服者：击败首个首领。
- 构筑大师：单局集齐 4 武器 + 4 被动。
- 无尽回响：存活 10 分钟。
- 成就只解锁一次；当前各项奖励依次为 100、150、200、250、300、300 回响。标题页可进入潮回声廊查看成就进度；局内打开时区分“本局达成、待结算”和“已解锁”。
- 局内新成就记在 `earnedAchievements/achievementRewards` 账本中，结算才统一入账；声音、角色偏好和局外购买不能清空或重置它。
- `finishRun()` 缓存结算摘要；UI 按 `summary.runId` 的 `Set` 和摘要对象的 `WeakSet` 在页面生命周期内幂等入账，重复展示结果不能重复发奖。`runId` 为种子加实例内序号；已结算集合不跨刷新持久化，刷新回标题重新开局，避免相同种子/序号的新局被旧记录误拦截。

## 8. 手机、横屏与桌面适配

- 手机横屏是推荐布局：摇杆左下、闪避右下、HUD 顶部居中、升级卡两列或紧凑三行；全部重视安全区 `env(safe-area-inset-*)`。
- 手机竖屏仍可游玩，但显示“横屏体验更佳”的轻提示，不强制暂停；旋转后自动重排 Canvas 与 UI。
- 触控目标最小 44px；升级卡可点，不依赖 hover；避免双击缩放和滚动。
- 桌面保留 WASD/方向键 + 空格/Shift；升级支持数字键 1/2/3、R 重抽、S 跳过。
- 屏幕宽度 ≤ 650px 或横屏高度 ≤ 520px 使用紧凑 HUD；玩家、敌人和地图坐标不因横竖屏改变，镜头只按新视口重算。
- 闪避仍为唯一主动操作，支持一指操纵摇杆、另一指闪避，分别释放互不干扰。

## 9. 数据结构（实现契约）

- `content.js` 实际导出：`CHARACTERS`、`WEAPONS`、`PASSIVES`、`ENEMIES`、`BOSSES`、`META_UPGRADES`、`ACHIEVEMENTS`、`ALTARS`、`PICKUP_TYPES`。波次由 `game.updateDirector()` 与 `nextWave/nextElite/nextBoss` 调度，不承诺独立波次配置表导出。
- `game.build = { weapons: [{ id, level, evolved }], passives: { [id]: level } }`；构筑属于游戏规则对象。
- `game.recalculateStats()` 把派生属性直接写入 `game.player`：`damageMultiplier`、`cooldownMultiplier`、`areaMultiplier`、`xpMultiplier`、`pickupChance`，以及生命/速度/吸取/闪避和月痕箭字段；没有独立 `stats` 对象。
- `game.runMeta` 在 `reset()` 开局时复制永久强化；局外购买与角色切换下一局生效，进行中的单局重算不得读取新购买的刻印。
- `game.start(characterId = null, seed = this.seed)` 保留固定种子复现入口；`GameUI.startRun()` 在正常游玩时生成新种子并作为第二参数传入。UI 的种子生成与局内确定性 RNG 分离，种子不属于存档字段。
- 周期武器运行计时器使用 `game.weaponClocks[id]`；月痕箭仍用 `fireClock`，刀刃另用 `orbitHits/orbitTrailClock/orbitBlades`，角度由局内时间计算。计时器、命中记录和弹体都不写入内容配置。
- 敌人附加 `behavior`、`state`、`stateClock`、`shootClock`、`chargeClock`、`fuse`、`elite`、`boss`；敌方弹体在 `game.enemyProjectiles`，玩家弹体在 `game.projectiles`，爆炸危险区在 `game.zones`。敌方弹体只伤玩家，bomber 危险区可伤双方。
- 存档模块与游戏规则解耦：`SaveStore/normalizeSave` 负责 schema、localStorage 及失败写入后的内存降级，入口直接复用；结算去重集合留在 UI 内存。购买逻辑与回响计算是可单测的纯函数。
- UI 从 `game.upgradeChoices/chestChoices` 读取候选，卡牌说明由 `game.describeChoice(choice)` 提供；候选由 `rollUpgradeChoices(chest)` 生成，应用入口为 `chooseUpgrade/chooseChestUpgrade`，重抽/跳过使用各自规则方法。
- 结算用 `game.runId/summary` 和 UI 已结算账本去重，成就使用局内 ledger，详见第 7.3 节；这些字段不能因打开局外页面或改声音偏好而被重置。

## 10. 验收标准

### 功能

- 3 角色可选/解锁；6 武器、6 被动、6 进化；4 武器 + 4 被动上限正确。
- 升级、重抽、跳过、宝箱三选一、进化都可用；选择后立即生效；连升和槽满行为正确。
- 8 种普通敌人、2 种首领、精英波次、3 个祭坛、4 种拾取物、危险区均存在。
- 结算回响、永久强化、角色解锁、成就、声音/角色偏好写入后刷新仍保留；损坏存档回退不崩溃。
- 手机横屏与竖屏均可开始、移动、闪避、打开升级卡、暂停、重开；桌面键盘快捷键可用。

### 自动测试

- 原有规则/音频/性能等价测试不回归。
- 新测试覆盖：构筑槽上限、确定性抽卡、进化条件、重抽/跳过、存档往返/损坏回退、成就一次性、首领阶段与掉落、敌人弹体不伤害敌人、移动端布局类存在。
- `npm test` 全绿。
- `npm run test:browser` 桌面 Chrome/Edge 全绿；增加手机横屏模拟视口验收和横竖屏切换截图。
- `npm run package` 成功，打包内容可静态部署。

### 性能

- 桌面 1440×900 下 600 敌人 + 4 武器同屏的平均帧时间不得比基线恶化超过 25%；粒子仍受预算控制。
- 手机模拟 844×390、低画质档下逻辑更新平均 < 8ms/帧（Node 基准），无持续新增对象导致的内存增长。
- 碰撞候选仍使用空间网格；敌方弹体数量有上限；渲染屏幕外实体仍跳过。

## 12. 风险与取舍

- 6 武器 + 8 敌人会显著增加状态量；优先使用数据驱动和现有空间网格，避免每帧创建大量对象。
- 敌方弹体只伤玩家；允许“走位借刀”的机制限定为 bomber 持续危险区，不能把它泛化为敌方弹幕友伤。
- 无尽模式的数值平衡无法仅靠自动测试证明；最终报告必须分别陈述已验证机制、尚未验证项目与真机试玩调参，不预设“机制验收通过”。
