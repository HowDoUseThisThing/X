## 性能与耐久

### 桌面更新和绘制

基线为 `9dbeb1b`，同一浏览器、1440×900、600 个可见且不死亡的静止敌人、最高画质、120 粒子预算。基线使用四发月痕箭，新版使用月痕箭/环葬刃/潮汐新星/引雷针四件进化武器。预热后交替测量 5 轮，每轮 180 帧，比较各轮平均耗时的中位数。

每帧计入 `game.update()`、Canvas 绘制及一次像素读回强制同步。最后复测为 **17.387ms → 19.146ms，增加 10.12%**，低于 25% 门槛；逐轮数值见 `output/frame-performance-validation.json`。

该方法包括 Canvas 读回开销，排除 DOM HUD、音频与垂直同步，不能当作真实手机 FPS 或整机游戏帧率。

### 逻辑与保留内存

- 同一 600 怪逻辑场景：基线 **0.0599ms**，四进化武器 **0.1917ms**，约 **3.20 倍**。新增武器增加了逻辑工作，绝对耗时低不能掩盖相对开销。
- 844×390、600 敌人的新版逻辑基准为 **0.1871ms/帧**，低于 8ms 门槛。逻辑测试不包含 GPU，也不模拟手机 CPU 性能。
- 两组四武器搭配各推进 **720 秒**，分别击杀 3930/3961、击败 3 个首领。使用无敌和自动选卡以稳定到达后期，这不是正常玩家通关或平衡性证明。
- 每 120 秒主动 GC 后采样，120～720 秒的保留堆增加分别为 **216176/210664 字节**，均约 0.21MiB，低于脚本的 2MiB 耐久阈值；后期采样有回落，没有观察到实体数量持续无限增长。这是受控耐久证据，不是无限时长的泄漏证明。
- 两组运行观测峰值：敌人 99、玩家弹体 48、敌方弹体 24、区域 17、效果 5、宝石 600、拾取物 100。另有满载规则测试直接验证各集合达到上限时的行为。

实体预算：敌人 800、玩家弹体 256、敌方弹体 240、区域 96、效果 128、宝石 600、拾取物 100。经验溢出合并保留总量；宝箱优先占位并在必要时合并次数；满额首领与精英会腾出普通敌人的位置。

## 复验与产物

```powershell
npm test
npm run test:browser
npm run test:strategy-browser
npm run test:performance
npm run test:frame-performance
npm run package
npm run test:release
```

浏览器脚本可通过 `CHROME_PATH` 选择可执行文件；`STRATEGY_FILTER` 可筛选策略浏览器用例。两项性能脚本需要完整 Git 仓库中可读取基线 `9dbeb1b`，静态游戏运行不需要 Git。

| 路径 | 内容 |
| --- | --- |
| `output/unit-validation.txt` | 单元测试输出 |
| `output/browser-validation-chrome.json`、`output/browser-validation-edge.json` | 原有浏览器检查 |
| `output/strategy-browser-validation-chrome.json`、`output/strategy-browser-validation-edge.json` | 63 项策略检查、几何证据与截图目录 |
| `output/touch-target-validation.json` | 两款浏览器的按钮实测尺寸、全量报告与最后标题专项报告路径 |
| `output/performance-validation.json` | Node 逻辑、实体峰值与 GC 后内存采样 |
| `output/frame-performance-validation.json` | 更新与绘制的基线对比 |
| `output/release-validation.json` | 包内文件一致性与手机流程验证 |
| `output/screenshots/packaged-*.png` | 包内入口的竖屏升级、横屏战场与结算截图 |
| `output/release/index.html` | 静态交付入口，需通过 HTTP 服务打开 |

交付包的 `validation/` 同时归档上述主要 JSON 报告和单元测试输出。浏览器原始截图及逐项记录的完整目录仍保留在工作区 `output/strategy-browser/`。
