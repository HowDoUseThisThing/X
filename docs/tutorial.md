# REA 重构教学素材：从网页版样本到原创生存游戏

作者：X先生。本文是最终 Markdown 教程，配套可运行的《夜潮生存：月蚀余烬》。

## 0. 先说边界：参考架构，不复制内容

本项目的输入是用户提供的 `真3A大作_V1.html`。它是一个自包含 HTML 游戏，包含 CSS、Three.js/WebGL 渲染、输入处理、HUD、启动流程和帧循环。教程只讨论可迁移的软件架构：如何观察模块边界、如何记录证据、如何把“玩法意图”重新表达成独立实现；不复制参考文件中的港区世界、角色、资产、原文案或具体关卡。

吸血鬼幸存者是玩法类型描述。本项目使用“夜潮生存/月蚀余烬”的原创名称与程序化视觉；它实现自动追踪攻击、移动躲避、经验宝石、升级三选一、难度随时间推进等通用系统。

## 1. 为什么用 REA

REA（Reverse Engineer Anything）是反向工程与运行时行为分析工具链，不是游戏引擎。它能帮助 AI 助教对一个已获得授权的程序建立证据链：输入是什么、哪些模块存在、哪些关系被静态观察到、哪些地方仍然未知。然后由人和模型根据证据重新设计代码。

本实验使用 REA 的 JavaScript 应用分析命令：

```bash
npx --yes rea-agents@6.8.0 analyze-javascript-application <absolute-app-dir> --json
```

分析结果只用于理解结构。静态分析不会证明“某函数运行过”，也不会自动把原游戏变成新游戏。

### 1.1 我们记录了哪些观察

对参考 HTML 做了安全的内联资源拆分：HTML 体量约 1.42 MB，内联 script 约 1.39 MB，样式约 31 KB。REA 6.8.0 在不执行 bundle 的前提下，报告了 189 个应用图节点和 217 条图关系；JavaScript 语义图保留到默认上限，包含 20,000 个语义节点和 20,000 个未知项。分析无解析失败，解析到 1 个 JavaScript 文件。完整静态分析的图覆盖为 partial，选择扩展受限项 512 条上限影响。

因此报告应写成“REA 观察到这些静态事实”，不能写成“完整还原了原游戏”。当前仓库的 `docs/rea-analysis.json` 保存了摘要、来源 SHA-256、限制和原始提取清单；未声称覆盖全部运行时行为。

## 2. 从观察到架构决策

### 2.1 参考样本的可迁移层

- **启动层**：boot -> 创建渲染器 -> 创建材质/场景 -> 创建输入 -> 创建游戏状态 -> 首帧。
- **循环层**：每帧取得 dt，更新输入、游戏逻辑、对象、特效、UI，再渲染。
- **状态层**：title、playing、paused、level-up、game-over 等状态互斥。
- **事件/反馈层**：命中、击杀、升级、受伤和暂停需要短暂反馈。
- **降级层**：音频、WebGL 扩展、触屏能力不可用时仍能进入游戏。

### 2.2 本项目的重构边界

```
index.html
  └─ src/main.js                 启动与 requestAnimationFrame
      ├─ core/input.js           键盘 + 触屏虚拟摇杆
      ├─ game/game.js            纯规则、状态机、确定性随机数
      ├─ render/canvas.js        Canvas 2D 程序化绘制
      └─ ui/ui.js                HUD、弹窗、升级选择和可选音效
```

这里主动把游戏规则从 DOM 和绘制中分离。这样 AI 生成的改动容易测试，也不会因为换视觉主题而改变升级规则。

## 3. 逐步实现玩法

### 3.1 确定性随机数

`src/core/math.js` 的 `mulberry32` 给每局一个种子：敌人出现类型、升级选项和粒子扰动都来自同一随机序列。好处是：复现 bug、写测试和做 AI 评测时，输入序列可以稳定复现。

### 3.2 游戏状态与主循环

`SurvivorGame` 只在 `playing` 状态累计时间。每帧顺序是：

1. 规范化并限制 `dt`，避免切后台回来时瞬移；
2. 根据输入更新玩家位置和闪避无敌时间；
3. 按随时间缩短的间隔生成敌人；
4. 自动寻找最近敌人并发射朝目标方向飞行的直线弹体；
5. 更新弹体碰撞、击杀和经验宝石；
6. 更新敌人接触伤害、粒子和拾取；
7. 经验到阈值后暂停进入升级三选一。

### 3.3 数据驱动的升级

升级对象只有 `id/icon/name/desc/apply`。UI 只读取 `id/icon/name/desc`，规则层调用 `apply`。这种数据驱动结构比“每个按钮写一套逻辑”更适合 AI 协作。

## 4. 从参考网页提取玩法需求的提示词

可以给 AI 助教这样的任务：

> 只分析我有权检查的本地网页。先列出静态观察、证据范围和未知项；再提炼“启动、输入、循环、状态、反馈、降级”这些抽象架构。不要复制资产、角色、文案或原始代码。使用新名称和程序化视觉，输出一个可测试的原创 Canvas 生存游戏。

如果使用 REA，要求它保留证据与限制：

- 结果来自静态文本，不能据此宣称运行时行为；
- 未选入分析范围的文件保持未知；
- 语义图达到保留上限时，报告 coverage/unknown，而不是把未知当作不存在；
- 对动态属性、网络请求和资源加载，只报告静态候选；
- 任何外部素材都先核对许可证与授权。

## 5. 运行、测试与验收

```bash
npm test
npm run serve
```

测试覆盖：

- 固定 seed 的敌人生成可复现；
- `dt` 被限制，玩家移动不会越界；
- 击杀生成经验并触发升级选择；
- 非当前选项不能被选择；
- pause/resume 不会偷偷推进时间；
- 本地服务器提供 HTML/JS/CSS，并拒绝路径穿越、未知路径和不支持的方法。

浏览器验收清单：

- 点击“开始生存”后能看到玩家、敌人、弹体、经验宝石和 HUD；
- WASD/方向键移动，空格或 Shift 闪避；
- 敌人被自动攻击，击杀后出现可吸收的经验；
- 升级弹窗出现且三项可选；
- P/Esc 可暂停，声音不可用时仍可继续；
- 手机端可用摇杆与闪避按钮；
- 3 分钟前后波次文案变化，受伤、击杀和闪避有视觉反馈。

## 6. 进一步教学：如何把它接到 AI 评测

给游戏加入可观测的 `<code>window.__MOON_SURVIVOR__</code>` 只用于本地教学调试：它暴露 game、renderer、input、ui，便于检查状态机和做浏览器自动化。生产版本应根据安全需要移除调试句柄。

可设计的评测任务：

1. 在 seed=42 时存活 30 秒；
2. 选择“余烬共鸣”后验证伤害倍率；
3. 模拟暂停，确保时间不前进；
4. 检查高密度敌人下仍使用固定 dt 上限。

评测的 reward 不应只看截图，还应读取可验证状态：`state`、`elapsed`、`kills`、`player.level`。这就是“视觉验收 + 状态验收”的组合。

## 7. 常见失败与修复

**失败一：把 REA 当成自动改写器。**

修复：REA 只提供静态/运行时证据；玩法、艺术方向、测试和授权仍由开发者决定。

**失败二：用原始 bundle 直接堆功能。**

修复：先写架构清单，再建立纯规则模块。把“最近敌人”“经验阈值”和“伤害”写成可测试的函数。

**失败三：只测启动，不测状态转换。**

修复：测试 title -> playing -> levelup -> playing/gameover，并测试暂停不会增加时间。

**失败四：忽略未知项和许可证。**

修复：在报告中明确 REA 的 coverage 与 unknown；本项目使用程序化绘制和自有文案，不把参考网页的资产或内容当作可再分发素材。

## 8. 结语

好的 AI 重构教程不是“复制一份大 bundle”，而是展示一条可审计的路径：

```
授权样本 → REA 证据 → 架构抽象 → 原创实现 → 自动测试 → 浏览器验收
```

本项目的最终成品由 X先生署名，保留了学习路径，也保留了未知与边界。

## 10. 从下载到录制：完整操作步骤

1. 安装 Node.js 22.12+（游戏本身使用 Node.js 20+ 即可；浏览器验收依赖要求更高），进入项目文件夹。
2. 运行 `npm test`，检查规则和 HTTP 服务。运行 `npm run serve`，浏览器访问 <http://127.0.0.1:4173>。
3. 点击“开始生存”。WASD 或方向键移动，空格/Shift 闪避；P/Escape 暂停或继续。手机使用左下摇杆和右下闪避按钮。
4. 靠近击败敌人留下的宝石，攒够经验后选择三项升级之一。敌人随时间变强。这是无尽生存模式，以生命耗尽结算；没有预设通关或 Boss 终点。
5. 结算显示本局时间、击杀、等级，点击“再入夜潮”重开。当前不持久化存档或最高纪录。声音按钮可切换程序化环境音与反馈音。

攻击会在开火时瞄准最近敌人，弹体随后沿直线飞行，并不会持续转向追踪目标。多重射击最多 5 枚，达到上限后不再出现该升级。

### 10.3 本轮修复如何用于教学

- **状态覆盖**：致命伤害发生后，同一帧经验拾取不应把 gameover 改成 levelup。限制升级检查仅在 playing 执行，并让死亡优先。回归测试构造同帧敌人与宝石，直接验证结算状态。
- **生命周期**：pagehide 取消帧回调；pageshow 恢复主循环并清空时间基线，避免返回页面后画面冻结。缓存页面保留音频对象。
- **输入清理**：失焦时同时清理键盘、摇杆和闪避状态，防止回到页面后角色继续移动。
- **升级有效性**：多重射击满级后从候选池移除，避免玩家选到没有收益的升级。

### 10.5 常见问题

- 双击 HTML 显示异常：浏览器可能拒绝 file:// 模块加载，请启动 HTTP 服务。
- 端口被占用：PowerShell 先设置 `$env:PORT = '4174'` 再启动，并打开对应端口。
- 手机访问：电脑和手机在同一局域网，设置 `$env:HOST = '0.0.0.0'` 后启动，访问电脑局域网 IP；按需允许防火墙。测试服务面向开发用途。
- 没有声音：先点击开始/声音按钮，使浏览器允许音频。无音频能力时游戏仍可运行。
- REA 输出不同：检查版本、输入 SHA-256、文件范围及分析限制，不据节点数判断游戏质量。

### 10.6 镜头坐标的常见陷阱：玩家为何跑到屏幕角落

画布绘制在世界坐标中，镜头平移应是 `屏幕中心 - 玩家世界坐标`。令 `ox = player.x - width/2`，那么正确平移等于 `-ox`。若再写成 `width/2 - ox`，就把中心偏移重复加了一次；玩家初始世界坐标 `(0,0)` 会被画到画布右下角附近，移动边界看起来也会很怪。

修复后，玩家不论如何移动，都保持在画面中心附近，场景与敌人相对玩家移动。烟雾震屏仍叠加在相机平移上。本轮浏览器验收还从 Canvas 画布读取玩家身体内部的像素，确认移动之后角色仍在屏幕中心，而不是只验证游戏数据里的坐标。
